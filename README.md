# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

注浆判定数据存在 `shield-tunnel-construction:v2`（旧的 `shield-tunnel-construction:entries`
首次打开时自动迁移：占位演示数据替换成新种子，真实存量记录按对应环次补档并按 v1 阈值判一遍）。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 同步注浆判定口径

同步注浆与浆液拌制共用一套判定逻辑（`src/data/grouting-config.ts` 定阈值，
`src/data/grouting-judge.ts` 出判定，`src/api/local-service.ts` 落事务）：

- **注浆量按配比设计用量判定**：每档配比（A/B/C）在阈值配置里有设计用量与允许区间；
  登记量**高于上限直接拒绝保存**，低于下限转待补浆（建议补浆量 = 设计值 − 实际值）。
- **注浆压力分区间且看持续时长**：峰值落在超限区间（≥0.45MPa）并持续 ≥30s，自动转
  待补浆并注明压的是哪个区间、建议补 0.5m³；只落在预警区间（0.30~0.45MPa）或超限但没
  持续够时间，只留痕不转待补浆。欠量与压力同时命中时补浆量取大者。
- **补浆挂回原编号**：补浆记录编号为 `原编号-B1/-B2`，带「原注浆编号」字段紧跟在主记录
  下，不另起一条；补浆量不足闭环会被拦下。
- **阈值版本化**：顶栏切到「值班管理员」后可在注浆页「判定阈值配置」里发布新版本，发布后
  已登记记录全部照新阈值重算；每条记录的「判定留档」按当时版本归档，历史不覆盖。
- **权限**：只有本注浆班组负责人能改该班组记录挂的浆液配比；注浆手只能用班组默认配比；
  跨班组、非注浆工种、管理员替班组提交一律拦下（责任班组以掘进环次台账为准，不由提交人选）。
  班组口头说法与登记的设计配比打架时，以登记的设计配比为准。
- **注浆与拌制对账**：登记必须选「检验合格、配比一致、剩余方量够」的拌制批次；注浆结论
  回写批次的已用/剩余方量与待用结论。注浆页和拌制页的「待补浆批次/记录」是同一份派生，
  统计只走 `groutingStats()` 一个出口，不两处各算。
- **幂等与事务**：同一登记/补浆/发布在 15 秒窗口内连点两回按头一回处理；所有改动先在草稿
  上跑完再一次性写 localStorage，写库失败就地撤销内存改动。

顶栏可切换当班身份（管理员 / 注浆一、二班负责人或注浆手 / 其他工种），用于演示上述权限。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。
